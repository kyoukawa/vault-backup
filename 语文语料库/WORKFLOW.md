
## 二、投料命名规则

```
/Note/语文/
├── 第二次呼吸/
│   ├── 《第二次呼吸》一稿（姜川）20260927.pages
│   ├── 《第二次呼吸》二稿（姜川）20260927.pages
│   └── 《第二次呼吸》二稿批阅单（姜川）20260927.pdf
└── 说论辩/ …
```

1. **一题一文件夹**，文件夹名 = 题目本身，不加编号、不加空格后缀
2. 文件名统一 `《题目》稿次（姜川）YYYYMMDD.扩展名`
3. `X 2` 这类重复文件夹是 iOS 拷贝冲突：先 `md5sum` 比对，相同的删，独有的并回主文件夹
4. **原件不搬走**（还要在 Pages 里改）

## 三、读料注意

- `.pages` 的正文**不在** `Document.iwa` 里，**只在 `preview.jpg`**
  → 解压 zip 后读图：`apple-vision ocr --source preview.jpg`
- `.pdf` 批阅单可直接读文本或 OCR

## 四、入库结构

`corpus/<编号>-<题目>.md`，每个单元包含：

```markdown
## <单元名>

- **原句**：（我写的原句，或老师给的示范）
- **为什么好**：（落在六维里的哪一维）
- **可迁移**：（什么场合能复用）
- **出处**：《说论辩》二稿 · 老师批注
```

避坑类另用：

```markdown
## 病灶：<名字>

- **表现**：（我写成了什么样）
- **老师原话**：（引用）
- **改法**：（正确写法）
```

## 五、跨篇病灶

两篇以上共有的问题，写进 `corpus/00-跨篇通用招法.md`。

已知的两条（重建时保留）：

- **题眼未对接** —— 用自己习惯的核心词替代了题目的词，导致全文偏离
- **首尾不回扣** —— 中间拆了要素，升华段没把结论收回来

## 六、复习队列

格式与 `REVIEW/due.sh` 解析规则一致：

```
| unit_id | type | 来源文件 | 单元 | learned | interval | next_recall | last_result | notes |
```

看今天到期：

```bash
TODAY=$(date +%F) sh REVIEW/due.sh
```

## 七、质量线

- 一条语料必须**能直接支撑一个论证步骤**，不能只是「好句子」
- 老师给的机制要**原样保留原话**，不要改写成自己的理解
- 同一个病灶不重复收录，合并到已有条目

## 八、整理检查清单（每轮入库后跑一遍）

1. **链接**：全库 wikilink 必须是 vault 根相对路径（`语文语料库/corpus/01-说论辩`），
   不写「首页」「INDEX」这类短名（双括号只给全路径）——vault 里 `语料库/`、`语文语料库/`、`阅读收集/` 都有同名文件，短名会跳到别的库。
   跨库指向英语库用 `[[语料库/INDEX|英语语料库]]`（英语库没有 `首页.md`）。
2. **元数据**：`corpus/*.md` 头部保留 front-matter（title / score / note / updated / tags）。
3. **计数**：INDEX「文件」表里的「N 原句 / N 机制句 / N 论据 / N 避坑」要与正文表格行数一致。
4. **队列**：新单元进 `REVIEW/recall-queue.md`，`unit_id` 不重复，`next_recall` 用 `YYYY-MM-DD`。
5. **图片**：`images/<题目>/<用途>-<页码>.jpg`，与语料引用一致；缺失时在 INDEX 待办里记一笔。
6. **备份**：整库推送到私有仓 `kyoukawa/vault-backup`（`/var/minis/shared/vault-backup`），
   它是异地副本，**不是工作区**——不要在里面直接编辑。
